1. Five-Minute Quickstart

Install the typed SDK in your backend service (Node.js ESM or CommonJS):

npm install @onelinebooking/sdk
import { OneLineBookingClient } from "@onelinebooking/sdk/server";

const olb = new OneLineBookingClient({
  baseUrl: process.env.OLB_API_URL,
  apiKey: process.env.OLB_API_KEY, // olb_test_... or olb_live_...
});

const slots = await olb.availability.get({ facilityId, fromDate: "2026-12-01", toDate: "2026-12-01" });
const hold = await olb.holds.create({ facilityId, slotRefs: [slots.slots[0].slotRef], externalCustomerId: "user-42" });
const booking = await olb.holds.convert(hold.id, { expectedAmountMinor: slots.slots[0].amountMinor, expectedCurrency: slots.slots[0].currency });

2. Authentication

Authenticate all server requests with Authorization: Bearer olb_test_... or olb_live_.... Secrets are stored strictly as SHA-256 hashes (`key_hash`) and matched in constant time. Tenant, project, environment, and scopes are derived server-side from the credential; mismatched X-Tenant-Id headers fail with 403 FORBIDDEN.

4. SDK Documentation (Browser vs Server Boundaries)

  • @onelinebooking/sdk/server: Full client + verifyWebhookSignature (requires Node.js; refuses secret olb_* instantiation in browser window).
  • @onelinebooking/sdk/browser: OneLineBookingPublicClient talks to your BFF proxy URL cleanly with zero secret keys in browser bundles.
  • Both ESM (import) and CommonJS (require) entrypoints are compiled and exported cleanly.

5. Booking Lifecycle

Two-phase holds prevent race conditions during checkout: active hold → convertHoldToBooking → confirmed booking → completed | cancelled | no_show. Expired or released holds free PostgreSQL GIST exclusion allocations atomically. Walk-in or pay-at-counter desks can call bookings.create directly.

6. Resource Configuration

Create physical locations and attach individual bookable resources (facilities). Schedules support weekday hours, overnight windows (endDayOffset: 1), breaks, calendar-date exceptions, slot overrides, buffer before/after rules, cancellation policy, and configuration revisioning (configurationRevision).

7. Availability Generation

Availability evaluates operating schedules in each facility's IANA timezone across DST spring-forward gaps and fall-back folds, applies outer buffers around contiguous multi-slot selections, and filters against active blackouts, holds, and bookings inside PostgreSQL repeatable-read snapshots.

8. Idempotency

Send Idempotency-Key on mutating calls. Requests serialize cleanly inside PostgreSQL via canonical request hash checks and advisory locks. Reusing a key with identical payload replays the exact response (`X-Idempotent-Replay: true`); reusing with a modified payload returns 409 IDEMPOTENCY_KEY_CONFLICT.

9. Error Handling

Every error returns { error: { code, category, message, retryable, retryAfterSeconds?, correlationId } }. Retry ONLY when retryable === true (HTTP 429 / 503) using exponential backoff while preserving the exact Idempotency-Key.

10. Webhook Verification

Verify X-OneLine-Signature: t=<unix>,v1=<hmac> using verifyWebhookSignature() within a 300s window. During secret rotation grace windows, multiple v1= signatures are included. Always deduplicate deliveries on X-OneLine-Event-Id (at-least-once delivery).

11. Rate & Concurrency Limits

Every API response returns X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset. Multi-instance limits coordinate via PostgreSQL counters and expiring tenant concurrency leases (429 RATE_LIMITED + Retry-After).

12. Test & Live Environments

Keys and tenants are strictly bound to test (olb_test_*) or live (olb_live_*). Cross-environment requests fail with 403 FORBIDDEN. Live environments enforce HTTPS-only webhook destinations with SSRF private/loopback/metadata IP blocking and disable the Console Playground.

13. Migration & Versioning Policy

API endpoints are prefixed with /v1; additive JSON fields are non-breaking. PostgreSQL migrations (0001..0006) are forward-only and additive to support rolling multi-instance zero-downtime deployments.
